# 研序 · 本地研究工作台 v0.3

面向单人、本机使用的论文研究工作台：汇集多平台历史 AI 对话，与不同厂商的模型和研究助手开展一对一或群组讨论，维护研究笔记、中英文稿件及引用，并从已有论文继续改稿。资料与项目保存在本机；在线模型、文献查询和外部 Agent 按所选连接调用。

Local-first research and bilingual academic writing workspace, with multi-provider AI discussions, historical conversation imports, manuscript revision, and citation exports.

## 从 GitHub 安装

当前启动脚本面向 **Windows x64**。需要先安装 Git 和 Node.js 22.12+（建议 Node.js 24），并能联网下载依赖。Python 和 uv 由项目脚本安装到工作区，不要求预装系统 Python。

```powershell
git clone https://github.com/David7583/yanxu-workbench.git
cd yanxu-workbench
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\bootstrap.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-Workbench.ps1
```

首次打开按向导选择资料与导出位置，并配置自己的模型服务。仓库只提供源码、示例配置和依赖锁文件，不包含个人对话、论文、数据库、凭据、已安装运行环境或编译产物。

- 顶栏“后台任务”汇总导入、讨论、论文分析与稿件生成。关闭面板、切换页面后继续，任务完成可回看结果；必须保持本机服务开启。

- 首页和聊天区均有明确的新建群聊入口。工作区默认“专注聊天”，提供宽幅对话画布、底部输入框、成员选择与回到最新消息；顶栏工具菜单可切换“并排写作”“专注写作”。

## 启动与停止

双击 **`Start-Workbench.cmd`**，启动本地服务并打开 **http://127.0.0.1:8765**。也可以在本目录运行：

```powershell
.\Start-Workbench.ps1
# 启动服务但不打开浏览器
.\Start-Workbench.ps1 -NoBrowser

# 停止这个工作区启动的服务
.\Stop-Workbench.ps1
```

关闭浏览器不会停止服务。停止前等待稿件显示已保存；遇到启动错误可查看 `.state/server-error.log`。停止脚本核对进程身份，不会仅凭端口结束其他程序。

## 首次配置与日常使用

未完成配置时，首次打开会显示三步向导：

1. **安排资料**：添加一个或多个来源目录，选择工作台数据位置及默认导出位置。来源目录、工作台数据库与导出目录是三个独立概念。保存目录不会自动导入所有文件。
2. **连接 AI**：添加厂商连接，保存 key，获取模型列表，从可搜索下拉框选择模型；可以添加多个连接并指定默认服务。
3. **准备就绪**：选择默认稿件语言和引用样式，进入工作台。

可以稍后继续配置；在“偏好设置”中重新打开向导。未配置模型时仍可整理资料、手动编辑和导出，系统不会生成模拟 AI 答案。

修改工作台数据位置后，需要停止并重新启动服务。启动脚本执行迁移，生成一致的数据库副本并复制相关资料后切换；新目录必须为空，新旧目录不能相互包含。当前目录和迁移状态以设置页为准，原始来源目录不随之移动。

“阅读与交互”提供舒适／紧凑密度，以及跟随系统、完整或减少动画选项。流程动效说明任务所处阶段，减少动画后仍显示状态。

## 多厂商、多模型

AI 服务管理内置 26 个连接模板，包括 OpenAI、Anthropic／Claude、Google／Gemini、DeepSeek、阿里云百炼、xAI／Grok、Moonshot／Kimi、智谱／Z.ai、火山方舟、腾讯混元、百度千帆、MiniMax、StepFun、SiliconFlow、Mistral、Groq、OpenRouter、Together、Fireworks、NVIDIA、Perplexity、Ollama、LM Studio 及自定义服务；其中有区域模板。

- 每个连接独立保存名称、地址、凭据、默认模型和启用状态。同一家厂商可配置多个连接。
- 支持添加、编辑、停用、删除连接；厂商模板可以隐藏并恢复。删除连接后，已有发言及其来源记录保留。
- 支持 OpenAI Chat Completions 兼容协议、OpenAI Responses、Anthropic Messages、Gemini GenerateContent 四种调用方式。本地 Ollama／LM Studio 使用兼容接口。
- “获取模型列表”用于读取当前服务公布的模型；“测试模型”另外发送一次简短生成请求，可能计入服务商用量。
- 列表不可用时可手动填写模型 ID；区域地址、企业网关、专用部署或推理接入点可在连接中修改。
- 旧版单服务配置会迁移为独立连接。API key 存入系统凭据库，不进入普通配置或项目数据库。

**厂商模板不代表所有账号、区域和模型都已实测。** 模型列表可见也不保证当前账号具备生成权限。部分服务不提供兼容的模型列表，特殊模型参数、图片／音频输入、厂商内置工具等能力尚未统一适配。当前主要面向文本研究与写作。模板附有官方文档链接；具体地址和权限以厂商控制台为准。

## 一对一与研究群聊

一个论文项目可以拥有多个讨论。新建讨论时选择一对一或研究群聊，再添加模型或已启用的研究助手。模型能力、讨论职责与 Agent 技能分别配置。

群聊支持：

- **点名回应**：只请求选定成员。
- **全体回答一轮**：成员并行回答同一问题。
- **多轮交叉讨论**：最多三轮；同一轮成员看到相同的先前讨论，下一轮可以回应上一轮结果。可指定一位主持人追加最终总结。

每轮最多选择八位成员。界面显示参与成员、进度及预计调用次数，可停止讨论，也可仅重试失败或中断的成员。解散后讨论变为只读，聊天记录、论文和引用仍保留。

成员可选择近期完整发言、仅加入后的发言或历史发言片段。全部模式都受上下文容量限制；“历史发言片段”是按消息截取的有界材料，不是全量历史，也不是经过独立核验的摘要。

消息记录成员名称、请求时的厂商和模型、时间、来源、上下文消息及使用的技能版本。服务返回实际模型版本或用量时，调用记录会显示这些信息；服务没有提供时不会推断。旧版消息未记录模型的情况会保留“未提供”。更换成员模型只影响之后的发言。

当前按成员的请求完成情况陆续展示回复，**尚非逐字流式输出**。多个 AI 意见一致不构成事实核验；稿件修改依然需要审阅。

## 历史资料：目录扫描、批次导入与来源追溯

在资料库中选择已配置的来源目录，或选择具体文件，先扫描候选项，再勾选需要导入的批次。支持：

- ChatGPT 单文件及新版分片 JSON、Claude、DeepSeek、Grok、千问的已适配导出结构。
- 包含可识别聊天文件的 ZIP：直接读取聊天成员，不把整包附件解压到工作区。
- Gemini Takeout 的活动 HTML，以及 Markdown、TXT、常见聊天 HTML 和通用消息 JSON。

目录扫描会区分聊天、可选文本资料和其他文件；账户资料、邮件、地图活动等不会因为位于导出目录就默认成为论文材料。Gemini 活动记录可能缺失完整问答，导入结果会显示相应提示。

相同文件通过 SHA-256 核验；有稳定对话／消息 ID 时保留来源批次、分支和内容变化，旧快照不会直接覆盖已识别的新版本。没有稳定 ID、时间或角色的资料保留不确定性，不能保证所有跨格式副本均自动合并。文件大小相同只是扫描阶段的重复提示。

每条历史消息尽量保留原始发言者、角色、模型标识、时间／时区、修改信息和来源。对话级默认模型与消息级模型分别记录；没有字段时显示未提供，不用导入时间或当前默认模型填补。

目录／ZIP 导入任务可以取消并续接，已处理记录通过检查点跳过。续接会重新读取前部数据，并非从任意压缩字节位置恢复；源文件改变时须重新扫描。旧式单文件上传任务仍可重新上传并去重。目录导入引用原始文件位置，原文件应继续保留，备份时也需备份这些来源。

### 导入与检索边界

- 浏览器单文件上传：JSON 最大 1 GB；HTML／Markdown／TXT 最大 64 MB。
- 目录导入按记录读取；ZIP 中聊天成员总展开量限制为 20 GB，单成员最大 2 GB，并检查异常压缩比例。HTML 成员仍受 64 MB 限制。
- 单条特别大的对话仍需整体处理；目录扫描上限为 100,000 个文件，过大时应选择更具体的目录。
- 资料检索使用全文索引、关键词和中文子串及有限上下文；**尚未实现语义向量检索、全库主题聚类或跨语言语义召回**。
- 聊天附件保留关联信息与原始位置，尚未统一解析图片、音频、视频和各种附件正文。

## 技能库与研究助手

“技能与助手”提供两种互相配合的管理对象：

- **技能**：扫描指定目录中的 `SKILL.md`，导入说明、编辑内容、启用／停用、查看版本及恢复旧版本。可从项目已完成的讨论提炼技能草稿，审阅后再启用；也可导出 `SKILL.md`。
- **研究助手**：创建职责与工作流程，选择默认模型并绑定技能；可扫描 `*.agent.json` 配置。启用后的助手可以加入讨论。

技能说明可以使用模板和参考资料，但当前运行方式以载入已保存的说明文本为主。**包含脚本的技能不会自动执行脚本，尚未实现完整资源包执行环境。** 新提炼的技能默认停用，保留来源讨论和生成模型记录；当前没有自动评测或自动晋升为已验证技能的机制。

外部 HTTP Agent 使用工作台的明确接口约定，而非任意软件自动兼容：

```json
{
  "protocol": "workbench-agent-v1",
  "messages": [{"role": "user", "content": "研究问题"}],
  "project_id": "...",
  "context": {},
  "instructions": "已配置的助手与技能说明",
  "skills": [{"id": "...", "name": "...", "version": 1}]
}
```

工作台向配置的 endpoint 发送 POST，请求可使用独立、与地址绑定的 Bearer 凭据。服务须返回 JSON `{"content":"回答文本"}`，也接受 `text` 字段。外部助手无需再绑定工作台中的厂商模型；其实际执行能力由外部服务决定。

**MCP 配置目前只能以停用状态保存，不能执行 MCP 工具或启动 MCP 进程。** 工作台没有安装 WSL、Docker 或代码执行沙箱，也不会因扫描到 Agent／skill 就运行其中的程序。`.venv` 只隔离 Python 依赖。

## 从已有论文继续改稿

在项目中打开“原稿与改造”入口，上传 DOCX 或 PDF。工作台保存独立原稿与哈希，按 Word 结构块或 PDF 物理页提取文本，随后可以：

1. 核对提取结果和警告，选择整篇或本次处理的章节／段落。
2. 填写目标期刊／读者和研究重点，生成区分表达、论证、方法和证据缺口的诊断。
3. 选择中文、英文或双语，生成改稿建议。
4. 审阅内容与引用后点击采用，或保留当前稿件；旧版本仍保留。

原稿单文件最大 64 MB，提取文本总量最多 200 万字符，长文按约 24,000 字符分段完整分析，最多并发两段后汇总。**没有 OCR**：扫描版 PDF 需要先进行文字识别。图片、公式对象、脚注、批注及复杂阅读顺序未完整还原，须对照原件；Word 结构块编号不是页码。

**生成的稿件只是建议，必须由用户采用。** 采用会替换对应笔记／稿件字段，旧内容进入版本历史；选择章节后生成的建议也不会自动定位合并进现有全文，采用前需确认范围。存在版本冲突时拒绝覆盖。

输入期刊名称并不意味着已经核查最新投稿要求。该流程不会自动补做研究、自动检索新文献或保证发表；原稿引用也不会因导入而变为已验证引用。可以先通过项目文献库补充核验材料，再生成建议。

## Zotero 与 Obsidian

### Zotero

在“科研工具”中选择 Zotero，先打开 Zotero 并在高级设置中允许本机其他应用通信。默认本地 API 为 `http://127.0.0.1:23119/api`，个人库标识为 `users/0`。

连接后可以读取文献集合、搜索条目、查看可读取的笔记和附件元数据，并将所选父级文献加入项目引用库。重复 DOI 或已有关联优先复用，保留 Zotero 条目身份。现有人工维护的书目不会因再次导入而被静默覆盖。

当前以**只读接入和手动选取导入**为主，不向 Zotero 写回，也没有持续双向同步；查看附件记录不代表已下载或读取 PDF 全文。界面主要支持本地库，云端 API 的授权属于高级接口配置。

导出的 Word 当前使用排好版的引用文本，**不是可由 Zotero Word 插件继续更新的活动引用域**。这是独立的后续能力。

### Obsidian

选择现有 vault 及工作台导出子目录，按名称扫描 Markdown 笔记、预览并在 Obsidian 中打开。选定笔记会附带来源链接追加到项目研究笔记，原笔记保持不变。

可以将研究笔记、中文稿或英文稿导出为 Markdown，附带项目及版本信息。已有同名文件会提示冲突；界面可使用新文件名导出，不会静默覆盖。当前是显式导入／导出，**没有自动双向同步或 vault 全文语义检索**。

## 写作、引用与导出

编辑器分别维护研究笔记、中文稿与英文稿，支持自动保存、版本历史和恢复。可根据所选讨论生成双语建议；语言不同的版本仍需人工检查数字、引用和结论是否一致。

- Crossref 查询获得书目元数据和可能存在的摘要；书目存在不代表已经阅读全文或确认论点。
- `[@ref_文献ID]` 保存结构化引用，阅读预览与导出共用 CSL 引擎，支持 APA、IEEE、GB/T 7714—2015 顺序编码样式。
- 导出可选择语言及 Word、PDF、Markdown、LaTeX、BibTeX。每批输出基于同一份已保存快照，写入配置的导出目录。
- 普通整稿生成仍有长度保护：笔记与两版稿件合计超过 60,000 字符，或目标字段超过 30,000 字符时，应改用章节处理；尚无段落级双语自动同步。
- 检测到复杂 Markdown 时可用源文模式保护内容。Word／PDF／LaTeX 的复杂表格、公式及期刊版式仍需复核；LaTeX 为需另行编译的 XeLaTeX／ctex 源文件，引用已排成文字，尚无可重新排版的 `\cite` 命令。

## 数据、网络与备份

项目、索引、讨论、版本和上传原稿保存在选定的本地数据目录。厂商和 HTTP Agent 的凭据保存在 Windows 系统凭据库，绑定到对应连接及地址。更换地址不会自动把旧 key 发往新地址，凭据也不随普通项目导出迁移。

本地导入、搜索和手动编辑不调用在线 AI。执行在线讨论、稿件诊断、改稿或技能提炼时，选中的材料与有限上下文会发送到所选服务。群聊会发送给参与成员对应的厂商／Agent；公开文献检索会把检索词发送给 Crossref。服务仅监听本机。

备份前停止服务，再复制完整的实际数据目录、`.state/storage.json`（存在时）、需要保留的导出文件，以及目录导入引用的原始资料。不要在运行时仅复制 SQLite 主文件，因为未合并的数据可能仍在 WAL 文件。当前没有一键整库恢复向导；迁移前保留完整备份。API key 需在目标电脑重新配置。

## 技术栈与独立环境

- 界面：React、TypeScript、Vite、Tiptap、Markdown、CSS 动效及减少动画支持。
- 服务与存储：Python 3.13.18、FastAPI、Uvicorn、SQLite／WAL／FTS5。
- 导入与连接：ijson、BeautifulSoup、httpx、系统 keyring。
- 原稿与输出：python-docx、pypdf、citeproc-py、ReportLab；未依赖 Pandoc。

```text
backend/                 API、数据、模型、群聊、技能、原稿及工具联动
frontend/src/            界面源码
frontend/dist/           构建后的界面
assets/csl/              引用样式及来源记录
tests/                   回归测试
scripts/                 环境、构建与开发脚本
data/                    默认数据位置；可在设置中调整
exports/                 默认导出位置
.tools/                  工作区独立 uv 与 Python
.venv/                   Python 虚拟环境
.cache/                  依赖与临时缓存
```

工作区安装独立 uv 0.13.7、Python 3.13.18 和 `.venv`，未修改系统 Python、全局 PATH 或 Python 注册表。前端构建使用电脑已有的 Node.js／npm；本工作区环境为 Node.js 24。Python 版本固定于 `.python-version`，依赖锁定在 `uv.lock`、`package-lock.json`。搬动工作区后应重建虚拟环境。

`config/settings.example.toml` 是早期示例；当前界面设置写入 SQLite，不读取该模板。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
```
